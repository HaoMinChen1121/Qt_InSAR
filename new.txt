InSAR 配准结果出现 Range（距离向）位移的原因分析与排查方案

一、现象描述

在 Sentinel-1 SLC 配准后，发现辅影像相对于主影像存在明显的 Range 方向偏移。

表现形式：

- 配准后的影像整体向距离向偏移；
- 互相关峰值存在稳定的 range shift；
- azimuth 方向可能正常，但 range 方向存在系统性误差；
- 干涉图可能出现条纹、低相干或局部失配。

该问题通常不是简单的 sinc 插值问题，而更可能来自：
1. SAR 几何模型误差；
2. TIFF/SLC 数据读取错误；
3. Range 坐标定义错误；
4. 多普勒/斜距时间处理错误。


==================================================
二、主要可能原因
==================================================


1. Range 时间轴计算错误（最高概率）

Sentinel-1 SLC 的 Range 方向不是普通像素坐标，而是由：

slant range time = azimuth time + range sampling time

确定。

关键 XML 参数：

annotation/*.xml

需要正确读取：

<slantRangeTime>
<rangePixelSpacing>
<sampleType>
<numberOfSamples>
<firstRangeTime>


正确关系：

range_index = (rangeTime - firstRangeTime) / rangeSamplingInterval


如果：

- firstRangeTime 使用错误；
- rangePixelSpacing 转换错误；
- sampling interval 计算错误；
- 米 → 像素转换错误；

会导致整体 range 偏移。


检查：

打印：

firstRangeTime
rangePixelSpacing
numberOfSamples

比较 master/slave。

如果两个影像 range 起始时间差：

Δt

对应像素偏移：

shift = Δt * c / (2 * rangePixelSpacing)


例如：

1 ns 时间误差：

≈0.15 m slant range

可能产生多个像素误差。


==================================================
2. Sentinel-1 TIFF 读取方向错误

Sentinel-1 measurement TIFF：

不是普通图片。

需要注意：

Raster：

column → range
row → azimuth


如果读取时：

- 行列交换；
- 左右翻转；
- byte order 错误；
- CInt16 高低位错误；

会产生 range 偏移。


检查：

原始 SLC：

pixel(0,0)

与 SNAP 打开的结果比较。


重点检查：

TIFF SampleFormat:

Complex Int16

数据排列：

I,Q,I,Q...


即：

sample[0] = real
sample[1] = imag


不能：

real + imag 读取错误。


==================================================
3. Burst 切分错误（TOPS IW重点）

Sentinel-1 IW SLC：

不是连续条带。

结构：

IW1
 ├ burst0
 ├ burst1
 ├ burst2
 ...


每个 burst：

range方向连续

azimuth方向分块。


如果：

burst 起始行错误：

burstFirst = y / linesPerBurst


或者：

burst overlap 处理错误：

会导致：

azimuth 偏移

但也可能影响二维相关峰。


检查：

XML:

burstList

关键字段：

azimuthTime
firstValidSample
lastValidSample


==================================================
4. Doppler / TOPS deramp 参数错误


TOPS SLC 在 azimuth 方向存在：

steering Doppler


需要：

deramp

reramp


如果：

doppler centroid 错误；

azimuth FM rate 错误；

burst 时间错误；


可能导致：

二维相位变化；

相关峰偏移。


XML:

dopplerCentroid

字段：

dcEstimateList

azimuthFmRateList


检查：

master/slave 是否分别使用自身参数。


==================================================
5. Range Doppler Geometry 没有考虑


Sentinel-1 SLC：

Range方向存在：

range migration


特别是：

burst边缘区域。


如果：

只做二维 FFT correlation：

可能估计到：

range shift

而实际是：

range migration


建议：

使用：

- coarse registration:
  cross correlation

- fine registration:
  oversampled FFT correlation


不要直接：

pixel peak

需要：

subpixel peak fitting。


==================================================
6. Sentinel-1 产品极化/通道错误


例如：

VV:

measurement-iw1-vv.tiff


VH:

measurement-iw1-vh.tiff


如果：

master:

VV

slave:

VH


或者：

IW1/IW2/IW3 对应错误：

会产生系统偏移。


检查：

SAFE:

measurement/

annotation/

calibration/


三者必须对应。


==================================================
三、针对当前项目 SentinelDataReader 的重点检查


当前架构：

ZIP
 ↓
自研 TIFF parser
 ↓
CInt16→SoA
 ↓
BurstCache
 ↓
SincResampler


重点检查：

1. TIFF Strip 读取

确认：

StripOffsets

StripByteCounts


读取：

offset + byteCount


不能：

以像素偏移计算文件位置。


--------------------------------------------------


2. Complex 数据排列


Sentinel-1:

CInt16:

I0,Q0,I1,Q1...


转换：

for(pixel)

real = int16[2*i]

imag = int16[2*i+1]


不要：

imag/real交换。


--------------------------------------------------


3. Range方向坐标保持


不要在读取阶段：

修改：

range index


保持：

原始：

sample 0 → range first sample


所有几何校正：

放在后续步骤。


--------------------------------------------------


4. SincResampler Range方向


重点检查：

公式：

output range position:

x_out

对应：

x_in = x_out + offset


确认：

offset符号。


常见错误：

应该：

slave(x+offset)


写成：

slave(x-offset)


导致整体range移动。


==================================================
四、推荐排查顺序


Step 1:

使用 SNAP 打开原始 SLC。


比较：

自己的 reader 输出

和 SNAP:

同一个 burst

同一个窗口


检查：

幅度图是否完全一致。


--------------------------------------------------


Step 2:

检查 XML 参数


打印：

firstRangeTime

rangePixelSpacing

numberOfSamples

azimuthTime


--------------------------------------------------


Step 3:

验证 TIFF parser


随机读取：

10×10窗口


与 GDAL RasterIO 对比：

complex pixel值。


--------------------------------------------------


Step 4:

关闭所有校正


仅：

读取
+
互相关


如果仍有 range shift：

说明是读取/坐标问题。


--------------------------------------------------


Step 5:

检查 Sinc 插值符号


测试：

offset=0

输出是否与输入完全一致。


测试：

offset=+1 pixel

是否向正确方向移动。


==================================================
五、当前项目最可能原因排序


根据目前项目架构：

概率排序：

1. SincResampler range offset 符号/坐标定义错误
★★★★★

2. Sentinel-1 XML firstRangeTime / sampling 参数没有正确参与
★★★★☆

3. TIFF CInt16读取或sample排列问题
★★★★☆

4. Burst range坐标没有保持原始sample编号
★★★☆☆

5. TOPS deramp参数影响
★★☆☆☆

6. GDAL/TIFF元数据问题
★☆☆☆☆


建议优先检查：

1. 配准前 master/slave 原始 SLC 是否已经存在 range 偏移；
2. SincResampler Range方向插值公式；
3. XML中的 firstRangeTime 和 rangePixelSpacing 是否正确使用。
